# Upstreaming the CW32L0 target definition to probe-rs

**TL;DR** — the CW32L012 currently needs
`--chip-description-path tools/CW32L0_Series.yaml` because the chip family does
not exist in probe-rs's built-in target list. The file is generated with
`target-gen` from the vendor CMSIS-Pack, so it can be upstreamed as-is.

Right channel: a **pull request against `probe-rs/probe-rs`**, not an email.
Maintainers only look at the issue tracker and PRs.

---

## What to submit

| Item | Value |
|---|---|
| File to add | `probe-rs/targets/CW32L0_Series.yaml` |
| Source | `WHXY.CW32L012_DFP` 1.0.2 (vendor CMSIS-Pack) |
| Generated by | `target-gen pack <pack file> <out dir>` |
| Family name | `CW32L0 Series` |
| Variants | `CW32L010x8`, `CW32L011x8`, `CW32L012x8` |
| Flash algorithm | `flashcw32l010` / `flashcw32l011` / `flashcw32l012`, page size `0x200` |
| Our local copy | [`tools/CW32L0_Series.yaml`](../tools/CW32L0_Series.yaml) |

The YAML in this repo was **not hand-written**: it comes straight out of
`target-gen`, which is exactly what probe-rs asks for
(<https://probe.rs/docs/knowledge-base/cmsis-packs/>).

## Step by step

1. Fork `probe-rs/probe-rs`.
2. Copy `tools/CW32L0_Series.yaml` to `probe-rs/targets/CW32L0_Series.yaml`.
3. Optional but recommended — regenerate it yourself so the PR proves provenance:

   ```bash
   cargo install target-gen
   target-gen pack WHXY.CW32L012_DFP.1.0.2.pack ./out
   cp ./out/CW32L0_Series.yaml probe-rs/targets/
   ```

4. Add a line to `CHANGELOG.md` under *Added*:

   ```
   - Added target support for the CW32L0 series (CW32L010x8, CW32L011x8, CW32L012x8)
   ```

5. Run `cargo xtask test` / at least `cargo build` and open the PR.

## PR description (copy-paste)

```markdown
### Add target support for the CW32L0 series (Wuhan Xinyuan / CMSemicon)

Adds `targets/CW32L0_Series.yaml`, generated with `target-gen` from the vendor
CMSIS-Pack `WHXY.CW32L012_DFP` v1.0.2. No hand edits.

**Variants:** CW32L010x8, CW32L011x8, CW32L012x8 (Cortex-M0+, 64 KB flash,
8 KB SRAM, 0x200-byte pages).

**Tested on hardware:** CW32L012 start-kit, ST-LINK clone over SWD, Linux and
Windows. `probe-rs download`, `probe-rs reset` and `probe-rs run` all work;
the flash algorithm erases and programs a 64 KB image correctly.

**Reference implementation:** a `no_std` HAL for this chip, including 32
examples that all run on the board, lives at
https://github.com/SunWithCloude/Rust_Cw32L012
(published as `cw32l012-hal` on crates.io).

Happy to regenerate the YAML from a newer pack or adjust formatting if needed.
```

## If a PR is not possible

Open an issue titled *"Target support request: CW32L0 series (CW32L012)"* and
attach the YAML; a maintainer can move it into `targets/`. Attaching the file
matters more than the text.

## Other places worth a short post (optional)

- `#embedded-rust` on the Rust Matrix/Discord — a 3-line intro plus the crate
  and repo links. This is where most embedded Rust users actually hang out.
- <https://users.rust-lang.org> → *Embedded* category — same content, longer
  lived.
- `awesome-embedded-rust` — a small PR adding the crate under *HAL crates*.

Keep every post short and factual: what the chip is, what the crate covers, one
measured number (e.g. "full-screen ST7789 frame in < 3 s at 24 MHz SPI"), and
the links. Long posts get skipped.
